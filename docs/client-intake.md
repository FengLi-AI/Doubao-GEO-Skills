# 先向用户询问客户信息

五个 Skill 默认处理当前用户的真实任务。先读取本次对话和用户明确提供的材料，只询问缺失或相互矛盾的信息。不要自动加载 `examples/`，也不要把原客户姓名换成另一个编造的客户来继续工作。

## 第一次接待

没有任何资料时，可以这样开场：

> 先了解一下这次要做的业务：品牌或机构叫什么、属于什么行业，主要提供哪些产品或服务，服务哪些地区？主要面向本地个人客户、全国用户、企业采购，还是几种业务都有？

根据回答整理品牌、行业、业务类型、产品或服务和区域；业务类型不明确时再确认，不擅自填“混合型”或“全国”。接着补问：

> 这次主要想让哪些客户看到内容？希望解决什么问题，或让读者采取什么行动？

分轮交流，每轮集中询问 2—3 组相关问题。用户已回答的部分直接使用；已有材料足够时直接进入工作，不重复要求填写整份问卷。推断与用户明确提供的事实分开记录，有歧义的推断先确认。

## 按任务收集

| 当前任务 | 需要先明确 | 随后按需询问 |
|---|---|---|
| 关键词 | 品牌、行业、业务类型、产品/服务、实际区域 | 目标客户、真实问法和优先业务 |
| 完整内容计划、写作 Prompt | 上述信息，加目标读者与本轮内容目标 | 转化动作、平台、可公开事实和来源 |
| 文章写作 | 客户背景、读者问题、用途和支撑关键事实的材料 | 资质、案例、数字的来源与公开范围 |
| 平台适配 | 主稿、目标平台、相关行业背景与来源 | 需要保留的客户表述、联系方式授权等；无需重问完整客户档案 |
| 豆包研究 | 目标品牌、实际查询词、研究阶段或待比较的记录 | 缺失的采集时间、模式、来源等；不编造回答或基线 |

用户说“暂时没有”时记录为暂无。没有资质、案例或已核验来源，不要求用户编造，也不把占位文字当证据。可以继续不依赖该信息的部分；依赖关键事实的正文等待资料补齐，或在用户明确调整范围后改写。

## 保存与脚本衔接

AI 助手把已提供的资料写入[空白 JSON 档案](../skills/doubao-geo-publisher/assets/client_profile.template.json)的工作副本，并列出仍待确认项。品牌简称、客户编号、客户阶段、行业敏感度等未提供时保持空白，不自动补值。

运行 `diagnose_client.py` 会得到 `client_intake` 和 `immediate_questions`。前者标记本轮规划所需字段；后者先列基础问题，基础信息齐备后才列来源、渠道等后续问题。

关键词、内容计划、Prompt 脚本缺少各自必要字段时，会在终端输出询问清单，返回退出码 2，不写出新的生成产物。它们不是聊天程序，提问与等待答复由 AI 助手或操作人员完成。应使用新输出文件，避免把以前的产物误认成本轮结果。

总流程缺少基础信息时只写诊断、`intake-questions.json/md` 和汇总，标记 `overall_status: incomplete`、`input_status: needs_input`，不生成关键词、内容计划或 Prompt。用户补充后更新档案，换一个空输出目录重新运行。

离线演示脚本与自动化测试会显式读取 `examples/` 中的测试数据；这是独立的功能验证入口，不参与正式客户接待。
